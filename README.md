# 신나는 도블! — 1차 버전

학생 기기 한 대가 도블 카드 한 장이 되는 수업용 웹게임. 기능 PRD와 DB·배포 기술 PRD의 1차 범위를 구현했다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 학생 | `index.html` (QR은 `index.html?room=코드`) | 코드와 닉네임으로 입장, 카드 보기, 찾았어요 |
| 교사 | `teacher.html` | 로그인, 세트 만들기/저장/불러오기, 방 열기, 진행, 종료 요약 |

## 파일

| 파일 | 내용 |
|---|---|
| `js/config.js` | Supabase 주소와 공개용 키. **비워 두면 데모 모드** |
| `js/dobble.js` | 카드 57장 계산(유한 사영평면), 기본 그림 57개, 원형 배치와 그리기 |
| `js/backend.js` | 모임 코드 입장, 덱 저장(서버 함수), 사진 줄이기, 실시간 채널 (Supabase 또는 데모) |
| `js/teacher.js` | 교사 화면. 판 진행자 역할(카드 배정, 점수) |
| `js/student.js` | 학생 화면 |
| `schema.sql` | Supabase 덱 테이블과 모임 코드 확인 함수 |

## 데모 모드로 바로 해 보기

`config.js`가 비어 있으면 로그인 없이 동작한다. 세트는 그 브라우저에 저장되고, **같은 브라우저의 탭끼리만** 통신한다. 실제 교실(여러 기기)에서는 Supabase 설정이 필요하다.

```bash
python -m http.server 8765
```

`http://localhost:8765/teacher.html`에서 방을 열고, 새 탭에서 `http://localhost:8765/index.html`로 학생 입장. (파일을 더블클릭해서 열면 모듈이 막혀 동작하지 않는다.)

## 실제 배포 (Supabase + Netlify)

교사는 **모임 코드 + 별명**으로 들어온다(이메일·구글 로그인 없음). 관리자가 코드를 오프라인으로 알려 주는 것이 곧 승인이다.

1. **Supabase 프로젝트** → SQL Editor에서 `schema.sql` 전체 실행.
2. **모임 코드 정하기**: SQL Editor에서 아래 한 줄을 실행한다. 코드는 암호화되어 저장되고, 이 줄은 파일에 남기지 않는다. 바꿀 때도 같은 줄을 새 코드로 실행하면 예전 코드는 막힌다.
   `insert into private.team (id, code_hash) values (1, extensions.crypt('모임코드', extensions.gen_salt('bf'))) on conflict (id) do update set code_hash = excluded.code_hash;`
3. **`js/config.js`**: Project URL과 공개용 키(`sb_publishable_...`). 비밀 키(`sb_secret_...`)는 절대 넣지 않는다.
4. **Netlify**: 이 폴더를 app.netlify.com/drop 에 끌어다 놓는다. 빌드 과정은 없다. 고친 뒤에는 사이트의 Deploys 화면에 다시 끌어다 놓는다.

덱은 모임 안에서 함께 본다. 내가 만든 덱(별명 기준)만 고치기·삭제 버튼이 보이고, 다른 선생님 덱은 복사해서 고친다. 서버에서 막는 것이 아니라 서로 믿는 모임을 전제로 한 화면 규칙이다.

## 이 저장소를 가져다 쓰는 선생님께

`js/config.js`에는 원래 만든 사람의 Supabase 주소가 들어 있습니다. 직접 쓰려면 **본인 Supabase 프로젝트를 만들어** 위 1~3단계를 따라 `config.js`의 두 값을 바꿔 주세요. 그대로 쓰면 원래 모임의 무료 한도를 함께 쓰게 됩니다.

## 실시간 동작 방식

판 상태는 DB에 쓰지 않고 메시지로만 주고받는다. Supabase는 **받는 사람 수만큼** 메시지를 세므로(보낼 때 1 + 받는 사람마다 1), 방 하나에 길을 세 개 둬서 필요한 사람만 받게 한다. 보내는 쪽은 채널에 들어가지 않고 HTTP로 보낸다.

| 길 | 이름 | 듣는 쪽 | 신호 |
|---|---|---|---|
| 방 전체 | `dobble-코드` | 모든 학생 | `state` 판 상태, 효과음, 학생별 모둠, 끝난 모둠 (12초마다 반복) |
| 교사 우편함 | `dobble-코드-t` | 교사만 | `hello` 입장, `ping` 10초마다 접속 확인, `found` 찾았어요(지금 카드 번호 포함), `bye` |
| 학생 우편함 | `dobble-코드-s-학생id` | 그 학생만 | `welcome`, `reject`, `card` 카드 8칸 내용 |

### 몇 명까지 되나 (Supabase 무료 플랜)

무료 한도: 동시 접속 200, 초당 메시지 100, 한 달 메시지 200만 개, 메시지 하나 256KB ([Realtime limits](https://supabase.com/docs/guides/realtime/limits), [메시지 세는 법](https://supabase.com/docs/guides/platform/manage-your-usage/realtime-messages)).

| 한 방 학생 수 | 초당 메시지 (학생마다 10초에 한 번 찾는다고 가정) | 40분 수업 1회 |
|---|---|---|
| 20명 | 약 14개 | 약 3만 3천 개 |
| 30명 | 약 21개 | 약 5만 개 |

- 한 모둠 최대 56명(더미가 한 장은 남아야 함). 모둠은 최대 10개.
- 동시에 여러 방: 접속 200 기준으로 **20명 방 9개** 정도.
- 한 달: 20명 수업 **약 60번**.

- **모둠으로 나눠서 한다.** 시작 전에 교사가 "몇 모둠으로 만들까요?"에 답하고(처음에는 4명 안팎으로 제안), 배치 방식을 고른다.
  - 랜덤: 접속한 학생을 무작위로 고르게 나눈다(22명 5모둠 → 5·4·5·4·4명).
  - 입장 순: 들어온 순서대로 앞에서부터 나눈다.
  - 직접: 학생마다 모둠을 고른다. 랜덤·입장 순으로 나눈 뒤에도 한 명씩 바꿀 수 있다.
  - 모둠이 정해지지 않은 학생은 시작할 때 인원이 적은 모둠에 들어간다. 한 명뿐인 모둠이 있으면 시작하지 않는다.
- **모둠마다 카드 더미를 따로 둔다.** 시작할 때 모둠마다 57장을 섞어 한 장씩 나눠 주고 나머지는 더미로 둔다. 찾으면 더미 맨 위 카드를 받고 쓰던 카드는 버린다(다시 나오지 않음). 학생은 같은 모둠 친구와만 비교하므로 모둠 안에서만 카드가 겹치지 않으면 된다.
- **모둠 더미가 바닥나면 그 모둠은 끝**("우리 모둠 끝!"), **모든 모둠이 끝나면 판이 끝난다.** 4명 모둠이면 모둠 안에서 모두 합쳐 53번 찾으면 끝.
- 게임 중 늦게 온 학생은 아직 진행 중인 모둠 중 인원이 가장 적은 모둠에 들어가 그 모둠 더미에서 한 장 받는다.
- '같은 방에서 한 판 더'는 모둠 배치를 그대로 두고 더미만 새로 만든다.
- 학생 카드 내용은 교사 기기가 메시지로 보내므로, 학생은 DB를 읽지 않는다.
- 교사·학생 모두 같은 탭에서 새로고침하면 방, 점수, 카드가 이어진다(탭 저장소 사용). 탭을 닫으면 사라진다.

## PRD 열린 항목에 대해 이 구현이 고른 것

| 열린 항목 | 고른 방식 | 바꾸려면 |
|---|---|---|
| 학생의 세트 읽기 | 교사 기기가 카드 내용을 메시지로 전달 | `teacher.js`의 `sendCard` |
| 교사 인증 | 구글 로그인 대신 모임 코드(암호화 저장) + 별명, 이메일 수집 없음 | `schema.sql`, `backend.js`의 `signIn` |
| 이미지 저장 | 파일 저장소 대신 긴 변 220px로 줄여 덱 안에 저장 | `backend.js`의 `uploadImage` |
| 기본 그림 세트 | 앱에 이모지 57개를 정적으로 넣음 | `dobble.js`의 `DEFAULT_ITEMS` |
| 도형 세트 | 서로 다른 도형 57가지(삼각형 6, 사각형 12 등)를 한 번씩만 사용. 색 8가지는 꾸밈용이고 한 카드에 몰리지 않게 배치, ±20도만 기울임 | `shapes.js` |
| 교사 새로고침 위험 | 탭 저장소에 판 상태 저장 후 복구 | `teacher.js`의 `saveRoom` |
| 방 코드 | 헷갈리는 글자를 뺀 6자리 무작위, 방 닫으면 폐기 | `backend.js`의 `makeRoomCode` |

## 확인한 것 / 못 한 것

- 데모 모드에서 확인함: 카드 57장 모든 쌍의 공통 항목 1개, 배치 2,000회 실패 0회, 입장 → 시작 → 찾았어요(점수 +1, 카드 교체) → 일시정지 → 교사·학생 새로고침 복구 → 종료 요약, 세트 편집(붙여넣기, 중복 경고, 저장, 미리보기), 휴대폰 화면.
- Supabase 실시간 채널: 두 연결 사이 메시지 전달, 240KB 메시지 전달 확인.
- 20대 동시 접속 시험은 아직 하지 않았다.
